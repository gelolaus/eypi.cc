# Dev Setup & Release Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make local full-stack setup a single command with clear preflight checks, and make each release a scripted, repeatable check followed by an ordered, owner-run deploy, without changing production behavior.

**Architecture:** Pure helper functions in `scripts/lib/` (unit-tested with Vitest) wrapped by thin Node CLI entry points in `scripts/`. No new dependencies. Deploys stay manual and owner-initiated: the scripts verify and document, they never deploy, migrate, or write to production.

**Tech Stack:** Node 20+ ESM (`.mjs`), Vitest 4, Vite 6, Vue 3 + vue-tsc, Cloudflare Workers via Wrangler 4, Hono, libSQL/Turso, GitHub Actions.

**Spec:** No separate spec exists. The requirements are the Goal above, plus the Context and Global Constraints sections below, which are the spec for this plan.

## Global Constraints

- No task deploys, runs `wrangler secret put`, applies a migration, or writes to production Turso or KV. Scripts may only read (`wrangler deploy --dry-run`, `GET` requests) and write local files.
- Never print secret values. Status output shows key names and states only.
- No new runtime or dev dependencies. Use Node built-ins (`node:fs`, `node:child_process`, `node:crypto`, `node:os`, `node:path`) and existing devDependencies.
- Scripts are ESM `.mjs`, Node 20+ compatible, and run on Windows and Linux. On Windows, spawn `npm` through `shell: true` (or `npm.cmd`), never bare `npm` with no shell.
- Local dev stays on the production Turso database. Do not add a dev database.
- Type fixes must not change runtime behavior: narrow types or type the response shape. No `as any`, no `@ts-ignore`.
- `.dev.vars`, `.env*`, and generated output stay gitignored. Do not commit generated files.
- Commit messages: Conventional Commits, lowercase imperative subject (match `git log`, e.g. `fix(links): ...`). Each task ends with a commit step. Do not push unless the owner asks.

## Review Focus

Five failure modes the request implies that no existing test exercises. Each names the task whose tests pin it.

1. A `.dev.vars` saved by a Windows editor has CRLF line endings and quoted values; a valid file must not be reported as broken. **Pinned in Task 2.**
2. Values containing `=` (base64 JWT secrets, PEM blocks, `==` padding) must not be truncated. **Pinned in Task 2.**
3. Values copied unchanged from `.dev.vars.example` (for example `your-turso-database-token`) must count as unset, not configured. **Pinned in Task 2.**

5. Releasing from a dirty tree or a non-`main` branch must be refused unless explicitly allowed. **Pinned in Task 5.**

```js
// scripts/lib/envFile.test.mjs
import { describe, it, expect } from 'vitest'
import { parseEnvFile, checkDevVars, seedDevVars } from './envFile.mjs'

const example = {
  TURSO_DATABASE_URL: 'libsql://your-database-name-your-org.turso.io',
  TURSO_AUTH_TOKEN: 'your-turso-database-token',
  JWT_SECRET: 'your-local-only-jwt-secret-min-32-chars',
  RESEND_API_KEY: 'your-resend-api-key',
  APPLE_TEAM_ID: 'XXXXXXXXXX',
}

describe('parseEnvFile', () => {
  it('parses CRLF files and strips one pair of surrounding quotes', () => {
    const text = 'JWT_SECRET="abc"\r\nTURSO_DATABASE_URL=libsql://x.turso.io\r\n'
    expect(parseEnvFile(text)).toEqual({ JWT_SECRET: 'abc', TURSO_DATABASE_URL: 'libsql://x.turso.io' })
  })
  it('keeps = inside values (base64 padding, PEM)', () => {
    expect(parseEnvFile('JWT_SECRET=ab+cd/ef==\n').JWT_SECRET).toBe('ab+cd/ef==')
  })
  it('skips comments and blank lines', () => {
    expect(parseEnvFile('# note\n\nA=1\n')).toEqual({ A: '1' })
  })
})

describe('checkDevVars', () => {
  it('counts example placeholders as unset', () => {
    const r = checkDevVars({ ...example }, example)
    expect(r.requiredUnset).toEqual(['TURSO_DATABASE_URL', 'TURSO_AUTH_TOKEN', 'JWT_SECRET'])
  })
  it('reports unset optional keys with their feature label', () => {
    const r = checkDevVars({ TURSO_DATABASE_URL: 'libsql://a', TURSO_AUTH_TOKEN: 't', JWT_SECRET: 's' }, example)
    expect(r.requiredUnset).toEqual([])
    expect(r.optionalUnset).toContainEqual({ key: 'RESEND_API_KEY', feature: 'verification emails' })
  })
  it('treats a copied XXXXXXXXXX placeholder as unset', () => {
    const r = checkDevVars({ TURSO_DATABASE_URL: 'libsql://a', TURSO_AUTH_TOKEN: 't', JWT_SECRET: 's', APPLE_TEAM_ID: 'XXXXXXXXXX' }, example)
    expect(r.optionalUnset.map((o) => o.key)).toContain('APPLE_TEAM_ID')
  })
})

describe('seedDevVars', () => {
  it('creates the file from the example with a fresh JWT_SECRET', () => {
    const r = seedDevVars('JWT_SECRET=your-local-only-jwt-secret-min-32-chars\nTURSO_AUTH_TOKEN=\n', null, 'NEWSECRET')
    expect(r.changed).toBe(true)
    expect(r.text).toContain('JWT_SECRET=NEWSECRET')
    expect(r.text).not.toContain('your-local-only-jwt-secret')
  })
  it('never overwrites an existing file', () => {
    expect(seedDevVars('JWT_SECRET=x\n', 'JWT_SECRET=mine\n', 'NEW')).toEqual({ text: 'JWT_SECRET=mine\n', changed: false })
  })
})
```

```js
import { describe, it, expect } from 'vitest'
import { checkGitState, checkFrontendBundle } from './releaseChecks.mjs'

describe('checkFrontendBundle', () => {
  it('flags a bundle built against localhost', () => {
    const problems = checkFrontendBundle([{ name: 'index.js', text: 'fetch("http://localhost:8787/api/links")' }])
    expect(problems.join('\n')).toMatch(/localhost:8787/)
  })
  it('passes a bundle built against the production API', () => {
    expect(checkFrontendBundle([{ name: 'index.js', text: 'fetch("https://api.eypi.cc/api/links")' }])).toEqual([])
  })
})

describe('checkGitState', () => {
  it('refuses a dirty tree unless allowDirty', () => {
    expect(checkGitState({ branch: 'main', porcelain: ' M src/App.vue\n', allowDirty: false, allowBranch: false })).toHaveLength(1)
```

### Task 8: Release runbook

**Files:**
- Create: `docs/RELEASE.md`

**Interfaces:**
- Consumes: `npm run release:check` (Task 5), `npm run smoke` (Task 6), the migration runner (`backend/run-migration.mjs`).
- Produces: one document an owner or another engineer follows top to bottom for a release.

- [ ] **Step 1: Write the runbook**

Sections, in this order:
1. **Before you start:** on `main`, clean tree, `git pull`. Run `npm run release:check`. Must exit 0.
2. **Schema (only if the release includes a migration):** apply the migration with `cd backend && node run-migration.mjs <file>` **before** deploying the backend. Migrations must be additive or backward compatible, because the frontend and backend deploy at different times. Destructive migrations need explicit owner approval (`CONTEXT.md`). Record the filename and date in your release notes (outside the repo, per D1).
3. **Verify secret names (read-only):** `cd backend && npx wrangler secret list --config wrangler.jsonc` should list `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `JWT_SECRET`, `RESEND_API_KEY`, plus wallet names if used. For the frontend, after `npm run build`: `npx wrangler secret list --config dist/eypicc_frontend/wrangler.json` should list `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN`. Confirm the frontend's list before the first release that relies on it; the code reads them for click logging.
4. **Deploy backend first:** `cd backend && npm run deploy`.
5. **Deploy frontend second:** from the root, `npm run deploy` (runs `predeploy` = release check, then `vite build`, then `wrangler deploy`).
6. **Redirects only if `redirects/` changed:** `cd redirects && npx wrangler deploy`.
7. **Smoke:** `npm run smoke`. All targets must `PASS`.
8. **Tag (after a good deploy, only when the owner asks to push):** `git tag vYYYY.MM.DD && git push origin vYYYY.MM.DD`.
9. **Rollback:** Workers keep prior versions. Check the current command with `npx wrangler rollback --help` before use; do not run it without owner approval.

Include a one-line rule at the top: "Backend before frontend. Additive migrations before both."
