# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Dark and True black themes with a System / Light / Dark picker and a True black switch, without a flash on load.

**Architecture:** The palette stays in `src/styles/tokens.css`: `:root` is light, `.dark` and `.dark.black` override it. A pure module (`src/theme/theme.ts`) parses the stored preference and resolves the theme. A tiny external script (`public/theme-init.js`) applies the classes before first paint, and a composable (`useTheme`) keeps them in sync at runtime. Components already use token utilities, so they change only where the picker is added.

**Tech Stack:** Vue 3, Tailwind v4 (`@theme inline` token mapping), reka-ui dropdown primitives, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-29-dark-mode-design.md`. Executors read it, especially the token table in section 1.

## Global Constraints

- Commits: Conventional Commits, `type(scope): lowercase imperative subject`, then `- bullet` lines starting with a lowercase verb. One commit per task, each green. **No `Co-Authored-By`, `Signed-off-by`, or any tool trailer** (`AGENTS.md`).
- Each task's checkboxes in this file are ticked in that task's own commit (`AGENTS.md` definition of done).
- Tests are written first, seen failing, then pass. `npm run typecheck` and `npm test` pass at the end of every task.
- `dark:` Tailwind utilities stay banned (`design.test.ts` legacy list). The theme is applied through tokens only.
- Brand hex `#35438c` and `#deac4b` appear only in `src/styles/tokens.css` (`design.test.ts`). The dark primary `#8b97d8` and the page backgrounds `#f5f5f5`, `#0a0a0a`, `#000000` may appear elsewhere.
- No hard-coded hex colours in `.vue` files, except the two existing allowances (`LoginView.vue` Microsoft logo, `ScannerPanel.vue` scrim).
- `index.html` has no inline script. The only scripts are `/theme-init.js` and the module entry. The CSP is `script-src 'self'`, so a same-origin file needs no header change.
- QR output stays dark on white in every theme. The Microsoft logo and emails are unchanged.
- UI copy and `DESIGN_SYSTEM.md` contain no em dashes. Controls are at least 44px, keyboard accessible, with visible focus.
- Stored preference key: `eypi.theme`. Default preference: `{ mode: 'system', black: false }`. Every storage read and write is in try/catch.
- Do not deploy or change Worker settings. The owner does that.

## Review Focus

Failure modes the spec implies that no feature test would otherwise cover, most likely first. Each line has its test in the task that owns the code.

- **Corrupted stored value** (`"null"`, `[]`, `{"mode":"neon"}`, a number) falls back to the default instead of throwing or applying nothing. Tested in Task 1.
- **Storage blocked or throwing** (private window): the picker still works for the visit and nothing crashes. Tested in Task 4.
- **System setting changes while the app is open** in System mode updates live, but a chosen Light or Dark does not move. Tested in Task 4.
- **True black chosen, then Light selected**: no `black` class is applied, and choosing Dark again restores True black. Tested in Tasks 1 and 4.
- **`theme-init.js` runs where `matchMedia` or `localStorage` is missing** and must not throw, falling back to light. Tested in Task 3.

### Task 4: useTheme composable

**Files:**
- Create: `src/composables/useTheme.ts`
- Modify: `src/main.ts` (call `initTheme()` before `mount`)
- Test: `src/composables/useTheme.test.ts`

**Interfaces:**
- Consumes: everything exported by `src/theme/theme.ts` (Task 1).
- Produces:
  ```ts
  export function initTheme(): void   // loads the stored preference, applies it, subscribes once to the system colour scheme
  export function useTheme(): {
    preference: Readonly<Ref<ThemePreference>>
    resolved: ComputedRef<ResolvedTheme>
    isDark: ComputedRef<boolean>
    setMode(mode: ThemeMode): void
    setBlack(on: boolean): void
  }
  ```
  State is module-level, so every caller shares it. Applying sets `dark` and `black` classes on `document.documentElement` and the `theme-color` meta, and saves the preference under `eypi.theme`.

- [ ] **Step 1: Write the failing tests** in `useTheme.test.ts` (reset modules and the document between tests):
  - Default with empty storage: mode `system`, `black` false.
  - `setMode('dark')` adds `dark`, saves `{"mode":"dark","black":false}`, and sets `theme-color` to `#0a0a0a`.
  - `setBlack(true)` under Dark adds `black` and sets `theme-color` to `#000000`.
  - **Black needs dark** (Review Focus): with black true, `setMode('light')` removes both classes and the colour is `#f5f5f5`; `setMode('dark')` again restores `black`.
  - **System live update** (Review Focus): in `system` mode, a `change` event from a fake `matchMedia` list flips the classes; in `light` and `dark` modes the same event changes nothing.
  - **Blocked storage** (Review Focus): with `localStorage.setItem` and `getItem` throwing, `setMode('dark')` still applies the classes and does not throw.
  - `initTheme()` reads a saved `{"mode":"dark","black":true}` and applies it; a corrupted value applies the default.
